## Planner prompt（步骤 6 用）

直接粘贴到 ChatPanel 输入框：

```
我要做一个面向玉柴发动机终端用户的「维修保养咨询」智能体。

业务流程：
1. 用户输入发动机故障/保养相关问题（中文）
2. 从知识库检索答案：用户维修保养说明书 + 发动机结构图 + 非电控故障树
3. LLM 基于检索结果生成图文结合的解答，标注引用来源
4. 如果置信度低于阈值，回复"建议提供发动机号/车架号转人工"

约束：
- 输入语言：中文（终端用户：农机司机、卡车司机）
- 不可向用户建议任何需要专业工具的诊断方式（端用户做不了）
- 答案必须基于知识库内容，不可编造
- 涉及非电控故障且明确有结构图时，在 sources 中列出结构图编号

输入：
- query: string（用户问题）

输出：
- answer: string（中文回答）
- sources: string[]（引用的知识库条目）
- confidence: number 0.0-1.0
- needs_escalation: boolean（confidence < 0.6 时为 true）

数据集：maintenance_manual_kb, engine_diagram_kb, non_ecu_fault_tree_kb
```

## 出错点 / 偏差

### 1. Planner 首轮 IR 验证失败（已通过 prompt 加约束解决）
- 现象：首轮 turn.failed，validator 报 `invalid reference at offset 0 in '${escalation_msg}'`
- 根因：planner 生成的 IR 引了悬空变量 `${escalation_msg}`
- 修法：prompt 显式禁止悬空变量引用 + 把固定话术直接写字面量字符串
- 文件：本文档「Planner prompt」一节已是修正后的版本

### 2. ❌ → ✅ artifact 下载 500（已修复并 merge）
- 现象：编译成功生成 zip/yaml 后点 Download 按钮"没反应"
- 根因：Starlette 用 latin-1 编码 Content-Disposition，`artifact_name` 含中文（"玉柴发动机维修保养咨询.zip"）触发 `UnicodeEncodeError` → 后端 500 → 前端 fetch 失败但 UI 无错误提示
- 修法：commit `adc0a43` — RFC 5987 双形式（ASCII fallback + `filename*=UTF-8''<encoded>`）
- 回归测试：`test_download_artifact_with_non_ascii_filename`

### 3. UI 状态滞后
- 现象：首轮 turn.failed 后 UI 仍显示"运行中" spinner
- 严重度：低；刷新页面解决
- 后续：M2 backlog 项（不阻断上线）

### 4. 工作台右栏过窄（已修复并 merge）
- 现象：CompileBar 在 xl 默认 col-span-2/12 = 17%，artifact 卡片挤压、Download 按钮（icon-only）几乎看不见
- 修法：commit `12beb12` — 引入 `react-resizable-panels@^3.0.6` 三栏可拖拽 + Reset Layout + Download 按钮加可见文字
- ADR：`docs/decisions/0029-resizable-panels.md`
